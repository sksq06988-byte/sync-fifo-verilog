# 同步 FIFO 波形阅读说明

本说明逐项核对了已归档的 [smoke VCD](../evidence/smoke/sync_w8_d4_s1_cycles100.vcd)，对应 [日志](../evidence/smoke/sync_w8_d4_s1_cycles100.log) 的配置为 `DATA_WIDTH=8、DEPTH=4、SEED=1、RANDOM_CYCLES=100`。以下具体时间和数据属于这份样例；修改配置后应重新依据实际波形判断。

VCD 的时间单位是 `1ps`，因此文件中的 `#55000` 表示 `55ns`。时钟周期是 `10ns`，激励通常在下降沿变化，FIFO 在上升沿接受操作。

## 打开与添加信号

使用任一支持 VCD 的查看器即可。VS Code 的 VCD 波形查看扩展是可选工具；安装后打开上述 `.vcd`，在信号列表中选择以下真实层级：

| 信号 | VCD 中的完整层级 | 用途 |
|---|---|---|
| 时钟 | `tb_sync_fifo.clk` | 找到实际采样的上升沿 |
| 复位 | `tb_sync_fifo.rst` | 判断该拍是否优先复位 |
| 写请求 | `tb_sync_fifo.wr_en` | 请求写入，不代表一定接受 |
| 读请求 | `tb_sync_fifo.rd_en` | 请求读取，不代表一定接受 |
| 写数据 | `tb_sync_fifo.wdata` | 被接受写入的数据 |
| 注册读输出 | `tb_sync_fifo.rdata` | 有效读后更新，其余时间保持 |
| 满标志 | `tb_sync_fifo.full` | 沿前用于决定是否接受写 |
| 空标志 | `tb_sync_fifo.empty` | 沿前用于决定是否接受读 |
| 占用计数 | `tb_sync_fifo.dut.count` | 检查容量及状态变化 |
| 写指针 | `tb_sync_fifo.dut.wr_ptr` | 检查写入、拒绝及回绕 |
| 读指针 | `tb_sync_fifo.dut.rd_ptr` | 检查读取、拒绝及回绕 |

本样例中 `wdata/rdata` 为 8 位，`count` 为 3 位，读写指针为 2 位。建议数据使用 Hex，计数和指针按需要使用十进制。

若使用支持正则的信号过滤框，可输入：

```regex
^tb_sync_fifo\.(clk|rst|wr_en|rd_en|wdata|rdata|full|empty|dut\.(count|wr_ptr|rd_ptr))$
```

列表可能显示 `wdata[7:0]` 等位宽后缀；搜索时使用信号名称，不必加后缀。可以另外添加 `tb_sync_fifo.dut.do_write` 和 `tb_sync_fifo.dut.do_read`，但须结合下面的沿前、沿后规则解释它们。

## 先看沿前，再看沿后

在 `rst=0` 的上升沿，实际接受条件为：

```text
接受写 = 沿前 wr_en && !沿前 full
接受读 = 沿前 rd_en && !沿前 empty
```

上升沿后，非阻塞赋值更新计数、指针、注册读输出；组合空满标志和 `do_write/do_read` 又随新状态重新计算。因此，光标正好落在上升沿右侧看到的 `do_write=1` 或 `do_read=1`，可能是供后续时钟沿使用的新条件，不能倒推该上升沿已经执行了访问。

检查一个边界时，先观察上升沿左侧的请求、空满状态，再观察右侧稳定后的计数、指针和输出。testbench 在上升沿后等待 `1ps` 再比较结果，所用原则与此相同。`rst=1` 时优先复位，不执行普通读写。

## 空读、写满与排空

先查看 `0–180ns`。下表的数据值使用十六进制，计数和指针使用十进制；`wr/rd` 是沿前请求。

| 上升沿 | 沿前请求与状态 | 本沿接受操作 | 沿后结果 |
|---|---|---|---|
| `45ns` | `wr/rd=0/1`，`count=0、empty=1` | 读被拒绝 | `count=0`，两个指针仍为 0，`rdata=00` 保持 |
| `55ns` | `wr/rd=1/1`，`wdata=31`，`count=0、empty=1` | 只写入 `31` | `count=1、empty=0`，写指针 `0→1`，读指针保持 0，`rdata=00` |
| `65ns` | `wr/rd=0/1`，`count=1、empty=0` | 读出 `31` | `count=0、empty=1`，读指针 `0→1`，`rdata=31` |
| `115ns` | `wr/rd=1/0`，`wdata=FA`，`count=3、full=0` | 最后一次可接受写入 | `count=4、full=1`，写指针 `0→1`，`rdata=31` 保持 |
| `125ns` | `wr/rd=1/0`，`wdata=FA`，`count=4、full=1` | 写被拒绝 | `count=4、full=1`，写指针仍为 1，`rdata=31` 保持 |
| `135ns` | `wr/rd=1/1`，`wdata=FB`，`count=4、full=1` | 只读出旧队首 `38` | `count=3、full=0`，写指针仍为 1，读指针 `1→2`，`rdata=38` |
| `165ns` | `wr/rd=0/1`，`count=1、empty=0` | 读出最后一个数据 `FA` | `count=0、empty=1`，读指针 `0→1`，`rdata=FA` |

`55ns` 沿后 `empty` 从 1 变为 0，使组合 `do_read` 变为 1；本沿读取仍被旧 `empty=1` 拒绝。写入的 `31` 到 `65ns` 才通过注册读输出，这是没有旁路的直接证据。

`115ns` 沿前尚未满，所以本沿可以写入；沿后才变满。`125ns` 的输入数据恰好也为 `FA`，不能仅凭数据值判断是否发生写入，应检查计数和写指针均未前进。

`135ns` 沿后 `full` 变为 0，使组合 `do_write` 变为 1；本沿依然使用旧 `full=1`，因此没有写入 `FB`。读指针前进而写指针保持，计数从 4 降为 3，是该边界行为的判断依据。

`165ns` 沿前仍有一个数据，所以最后一次读有效；沿后才变空。进入空状态不会把 `rdata` 清零，它保持最后一次有效读取的数据。

## 运行中同步复位

再查看 `530–550ns`。`535ns` 已写入 `A5`，使占用计数变为 1。复位发生在随后下降沿，不能把该下降沿误认为状态清零的时刻。

| 时间 | 时钟与复位 | 已核对的状态 |
|---|---|---|
| `540ns` | 时钟下降沿，`rst:0→1`，两个请求均为 1 | `count` 仍为 1，写指针仍为 3，读指针仍为 2，`rdata` 仍为 `ED`，`empty=0、full=0` |
| `545ns` | 时钟上升沿，`rst=1` | 复位优先：`count=0`，两个指针为 0，`rdata=00`，`empty=1、full=0` |

`540ns` 拉高复位到 `545ns` 上升沿之间仍保存旧状态，符合本设计的同步复位契约。

`545ns` 沿前 `do_write=1、do_read=1`，但时序逻辑执行复位分支，因此没有普通读写。沿后因 `wr_en=1、full=0`，组合 `do_write` 仍为 1；这同样不是“复位时写入成功”的证据。存储数组未被清零，但指针和计数清零后，旧内容不再是 FIFO 中的有效数据。

## 阅读后的自检

- 能根据沿前空满状态解释 `55ns` 和 `135ns` 为什么没有同时接受两个请求。
- 能指出 `65ns` 的注册读输出，以及 `125ns` 被拒绝写时保持的指针。
- 能说明 `115ns` 写入后才满、`165ns` 读取后才空。
- 能区分 `540ns` 提出复位和 `545ns` 执行同步复位。
- 能解释复位丢弃的数据为什么计入日志中的 `discarded`，并使用 `writes = reads + discarded` 检查守恒。

完整参数矩阵和扩展参数的复现方法见 [测试计划](test_plan.md)。这份短波形适合讲解已列出的边界，不替代完整回归、综合或静态时序检查。
