# 同步 FIFO 测试计划

本计划对应 [RTL](../rtl/sync_fifo.v)、[独立 testbench](../tb/tb_sync_fifo.sv) 和 [PowerShell 运行入口](../sim/run_sync_fifo.ps1)。所有命令均在仓库根目录执行。

## 设计契约

- 参数为 `DATA_WIDTH`、`DEPTH`，默认 `8×4`，均须为正整数。深度支持 `1`、`3` 等配置。
- 接口为 `clk、rst、wr_en、rd_en、wdata、rdata、full、empty`。
- 内部使用读写指针和占用计数器。地址宽度至少为 1，计数器可表示 `0..DEPTH`；指针到 `DEPTH-1` 后显式回绕到 0。
- 在上升沿到来前计算接受条件：`do_write = wr_en && !full`、`do_read = rd_en && !empty`。
- `rst=1` 时，复位优先于读写：在上升沿清零指针、计数和 `rdata`，得到 `empty=1、full=0`。不清空存储数组。
- 采用注册读：有效读在上升沿后更新 `rdata`；没有有效读时保持原值。不实现输入到输出的旁路。

以下行为均假定该上升沿没有复位。表中的状态是沿前状态：

| 沿前状态和请求 | 实际写入 | 实际读取 | 占用计数变化 |
|---|---:|---:|---:|
| 空，`wr_en=0、rd_en=1` | 否 | 否 | 0 |
| 空，`wr_en=1、rd_en=1` | 是 | 否 | +1 |
| 非空非满，`wr_en=1、rd_en=1` | 是 | 是 | 0 |
| 满，`wr_en=1、rd_en=0` | 否 | 否 | 0 |
| 满，`wr_en=1、rd_en=1` | 否 | 是 | -1 |
| 任意状态，两个请求均为 0 | 否 | 否 | 0 |

深度为 1 时没有“非空非满”状态，不能要求出现同一上升沿同时接受读写。

## 检查器时序

1. 激励在时钟下降沿更新，时钟周期为 `10ns`。
2. 上升沿先检查沿前空满标志与参考队列长度是否一致，再保存本拍接受条件。
3. 参考模型先读队首，再将有效写数据加入队尾；用接受事件更新模型指针。
4. 等待 `0.001ns`，即 `1ps`，让 DUT 的非阻塞赋值和组合标志更新，再比较 `rdata`、`full`、`empty`、两个指针和 `count`。
5. 复位时清空参考队列和期望读输出，将被丢弃的数据计入 `discarded`。

复位期间组合信号 `do_write` 或 `do_read` 仍可能为 1；时序逻辑优先执行复位分支，因此不能把这两个组合信号单独作为复位期间的实际访问证据。

## 定向覆盖

| 检查项 | 激励与判定 |
|---|---|
| 初始复位及复位优先级 | 复位期间同时拉高读写请求，检查指针、计数和读输出清零 |
| 空读 | 空时请求读，检查计数、指针和 `rdata` 保持 |
| 空时同时请求读写 | 只接受写，`rdata` 保持，到下一次有效读才输出该数据 |
| 写满及满写拒绝 | 连续写满，再请求写，检查容量不超过 `DEPTH` |
| 满时同时请求读写 | 只接受读，写指针保持，计数减 1 |
| 非空非满时同时读写 | 深度大于 1 时检查数据顺序、两个指针前进、计数不变 |
| 指针回绕 | 反复填充、排空，检查读写指针到末地址后回到 0 |
| 注册读与保持 | 有效读更新 `rdata`，无有效读及被拒绝的读均保持 |
| 运行中复位 | 定向制造非空状态后复位，并在随机阶段中途再次复位 |
| 结束排空及数据守恒 | 停止写入、有限次排空，模型长度为 0，且 `writes = reads + discarded` |
| 超时保护 | 排空等待和总仿真时间均有上限，超时使用 `$fatal` 判失败 |

随机阶段使用由 `SEED` 初始化的固定算法生成请求和数据。相同参数、seed 和随机周期数可用于复现失败。

## 回归矩阵

每个矩阵用例均先执行定向测试，再执行 `1000` 个随机操作周期；定向测试及复位等待不计入这 1000 个周期。

| DATA_WIDTH | DEPTH | SEED | 每个 seed 的随机周期数 | 用例数 |
|---:|---:|---|---:|---:|
| 8 | 1 | 1、7、42 | 1000 | 3 |
| 8 | 3 | 1、7、42 | 1000 | 3 |
| 8 | 4 | 1、7、42 | 1000 | 3 |
| 16 | 4 | 1、7、42 | 1000 | 3 |
| 合计 | | | | 12 |

执行完整矩阵：

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\sim\run_sync_fifo.ps1 -Matrix -RandomCycles 1000
```

不加 `-Matrix` 时只执行一个用例。复现单个矩阵用例，例如：

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\sim\run_sync_fifo.ps1 -DataWidth 8 -Depth 3 -Seed 42 -RandomCycles 1000
```

扩展参数检查为 `DATA_WIDTH=12、DEPTH=5、SEED=99`，随机阶段为 300 个周期，用于再次检查数据宽度变化及非 2 的幂深度：

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\sim\run_sync_fifo.ps1 -DataWidth 12 -Depth 5 -Seed 99 -RandomCycles 300
```

## 通过条件与证据

每个用例必须同时满足编译退出码为 0、仿真退出码为 0、日志包含 `SYNC_FIFO_PASS`。脚本任一用例失败会抛出错误；全部指定用例通过后，终端输出 `SYNC FIFO REGRESSION PASS`。

完整矩阵应有 12 份用例日志，每份起始行中的 `WIDTH、DEPTH、SEED、RANDOM_CYCLES` 都须与矩阵一致，不能仅凭总通过标记推断配置或随机周期数。扩展用例另检查 `12、5、99、300`。

运行生成物位于：

- 日志：`sim/logs/sync_w宽度_d深度_s种子.log`。
- 波形：`sim/waves/sync_w宽度_d深度_s种子.vcd`。

同一宽度、深度、seed 的重跑会覆盖对应生成物，文件名不包含随机周期数。长期证据应另按随机周期数归档；已归档的 [100 周期 smoke 日志](../evidence/smoke/sync_w8_d4_s1_cycles100.log) 和 [对应波形](../evidence/smoke/sync_w8_d4_s1_cycles100.vcd) 使用独立文件名保存。这份 smoke 样例不能替代上述 12 个 1000 周期矩阵用例。

关键时间点的逐沿检查见 [波形阅读说明](waveform_guide.md)。本计划描述检查方法；实际执行状态应以对应运行日志为准。功能仿真结论仅覆盖已测试行为，不等同于综合、布局布线、存储宏映射或静态时序验收。
